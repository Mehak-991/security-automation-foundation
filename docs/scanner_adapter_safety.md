# Scanner Adapter Safety Controls

## Purpose

The scanner adapter is designed for authorized local/lab security automation.
Its main purpose is to execute a permitted Nmap command only when the supplied
target passes the project's approval controls.

## 1. Approved Target Validation

The adapter reads targets from:

`approved_targets.txt`

Only targets listed in this file are accepted for scanner execution.

Current approved targets:

- `127.0.0.1`
- `localhost`

If a target is not present in the approved-targets file, the adapter raises a
validation error before starting Nmap.

## 2. Controlled Command Construction

The adapter constructs the Nmap command internally.

Current controlled command format:

`nmap -sT -n -p 1-1000 <approved-target>`

Arbitrary scanner arguments are not accepted from the user.

This keeps command construction separate from untrusted input.

## 3. Permitted Tool

The scanner executable is defined in:

`config/scanner_allowlist.yaml`

Current permitted scanner:

`nmap`

The adapter does not accept an arbitrary executable path from user input.

## 4. Timeout Protection

The scanner execution uses a configured timeout.

Current timeout:

`30 seconds`

If Nmap exceeds the timeout, the process result is recorded with:

- `return_code = -1`
- `timed_out = true`
- status `TIMEOUT`

## 5. Tool Version Capture

Before scanner execution, the adapter captures the installed Nmap version.

This provides reproducibility information for the recorded execution.

## 6. Controlled Evidence Path

Scanner evidence is written under:

`evidence/runs/`

The output path is generated by the adapter from the run ID and target.

The user does not provide an arbitrary output location.

## 7. Structured Audit Logging

Scanner activity is recorded in:

`evidence/run.log`

The audit log records information such as:

- timestamp
- run ID
- event
- status
- target
- command
- return code
- timeout status
- tool version
- evidence output path
- execution message

## 8. Rejection Before Execution

For an unapproved target, the adapter performs the approval check before
calling `subprocess.run()` for the scanner.

This behavior is covered by an automated unit test that verifies that
`subprocess.run()` is not called for an unapproved target.

## 9. Test Coverage

The Nmap adapter has automated tests covering:

- controlled command construction
- unapproved target rejection
- successful scan result handling
- timeout handling
- controlled evidence directory validation

The complete project test suite is currently passing.

## 10. Scope Limitation

This project is intended for authorized local/lab security automation.

The current implementation is not intended to provide unrestricted network
scanning or arbitrary command execution.
